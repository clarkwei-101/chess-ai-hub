### 1.3 架构问题 (中长期)

1. **EngineManager 单例 + globalThis pin**: 在 Vercel serverless 上每个 invocation 是独立容器,单例机制失效。当前靠 `await ensureStarted` 模式每次重启,但冷启动开销大。
2. **EngineManager 1500+ 行单文件**: 需要拆分成 `start/stop/move/analyze/set-style/ownership` 多个模块。
3. **没有持久化 session**: 用户登录(`/api/auth/login`)只在本地 dev stub,Vercel 上 session 永远空。
4. **GTP protocol 抽象**: `parseGtpInfoLine` 把 19×19 ownership 累积逻辑放在了 `handleLine` 里,跨函数状态。建议提取为 `KataGoInfoAccumulator` 类。

## 2. 围棋·象棋·国际象棋 大师评审

### 2.1 评分体系

```
本手 (Honest Move) — 局面下最稳健、最合棋理的选择,不犯错
妙手 (Brilliant Move) — 出人意料但逻辑严密,改变局面平衡
俗手 (Common Move) — 看似合理但本质上是模仿,缺乏深度思考
恶手 (Blunder)     — 明显违反棋理,损失巨大
```

(分类规则: `lib/analysis/move-classification.ts`,基于 winRate / scoreCp 漂移 + MultiPv 命中率)

### 2.2 Demo Mode 实战复盘 (Lee Sedol vs AlphaGo · Game 4 · Move 78 「神之一手」)

|---|---|---|---|
| 本手 | 22 | D16, N4, R5, P7, P9, O11 | 73% |
| 妙手 | 5 | F3 (白 4), B6 (白 14?), D6 (黑 16?) | 17% |
| 俗手 | 3 | C6 (黑 6), D4 (白 2, 旧定式) | 10% |

### 2.4 评审建议

**围棋**:
- 增加「死活题 / 手筋题」每日 5 题推送
- 增加「胜率曲线」实时显示从开局到当前的胜率漂移
- 增加「AI 复盘报告」:用 KataGo 跑全 50 手 + 标识 妙手/俗手

**中国象棋**:
- 缺少开局定式库 (中炮对屏风马 / 飞象局等),Pikafish 默认走「仙人指路」过于平淡
- 缺少「残局胜/和」判定 (单车必胜马双士等)

**国际象棋**:
- 缺少 Sicilian / KID / QGD 等开放开局的引擎推荐
- 「stockfish 18 + skill level 20」过于强大,建议加入 UCI_LimitStrength 模式
